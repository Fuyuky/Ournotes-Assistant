# 客户端构建与更新

自 v0.1.1 起客户端仅支持 Windows x64；Mac 支持及相关代码已移除。Linux 服务器不受影响。没有独立部署版或开发业务版；`devtools` 只放离线诊断工具，不进入发行包。

## 安装布局

```text
客户端目录/
  启动控制台.cmd
  boot.ps1
  boot_client.py
  release.json（包内签名清单）
  current.json
  update-public-key.txt
  versions/<版本>/app/
  versions/<版本>/runtime/
  user-data/config/
  user-data/data/catalog/snapshots/
  user-data/state/
  user-data/results/
```

`current.json` 选择程序版本。更新替换程序和启动器、补充固定素材，不能覆盖 user-data 中的配置、数据库和运行记录。成果、账号明细的永久副本只在服务器；本机 results 只用于待确认上传和必要恢复。初装资源只包含当前固定运行素材，不打包整套网站图集或历史快照。

Windows 双击 cmd。运行时随包提供，目标机不用另装 Python。MuMu 和游戏需要用户自行安装。

启动器通过随包 `boot_client.py` 等待本机接口与首页就绪（最多60秒），再打开浏览器。启动失败保留错误提示；早期启动日志位于 `user-data/state/webui/boot.log`，服务日志位于同目录的 `server.log`。超时不强制结束后台进程。

控制台的 MuMu 卡片可检测安装位置并保存目录至 `user-data/config/mumu.json`；只读扫描常见位置和 Windows 卸载注册表，不运行模拟器。多个候选需手动选择；运行任务期间不能修改。保存后后续操作读取新路径。显式保存的路径优先于环境变量 `OURNOTES_MUMU_ROOT`，失效时提示重新配置，不静默改用其他安装。

## 构建

正式发布由 `.github/workflows/release.yml` 在 Windows x64 runner 构建和检查。手动触发可选择仅验证或发布，通过后上传一个 Windows ZIP。`RELEASE_SIGNING_KEY` 放在仓库 Actions Secrets，私钥不进入源码、日志或产物。构建使用仓库内 `assets/runtime-catalog` 的固定素材，不依赖开发机的数据目录。

本机构建使用项目 `.venv` 的 Python。构建器按 `uv.lock` 导出 client 组，下载或接收平台对应 Python 运行时，安装平台依赖，不复制开发虚拟环境。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build_release.py `
  --version 0.1.1 --platform windows-x64 `
  --output results/build-release/正式构建 `
  --signing-key C:\私有发布目录\release-key.pem --download-runtime
```

首次生产密钥明确加 `--generate-signing-key`，以后复用同一私钥。私钥在项目外保存，初装只带公钥；临时验收密钥及用它生成的包不能冒充正式发行。已有运行时用 `--runtime` 和相应摘要；完整参数见 `--help`。统一免安装包必须包含运行素材。

每版只生成一个 `ournotes-<版本>-windows-x64.zip`，初装和控制台更新共用。Release 只上传 一个 Windows ZIP，不另发更新包、签名、公钥或校验码附件；GitHub 自动生成的 Source code 链接不是客户端发行包。

ZIP 内含 `release.json` 的 Ed25519 签名与全部文件摘要，客户端使用已保存公钥验证。清单不对包含它自身的 ZIP 计算自引用摘要，而是验证精确文件集合、每个文件内容、平台、版本和素材指针。下载从公开 Release 获取，无需用户配置 GitHub token。

包中排除账号、数据库、邮箱和接入凭据、Google授权工具、SSH配置、日志、结果、开发工具、测试、Git、缓存、旧版本、服务器后台源码。不能把已配置本机的 user-data 或 `client-connection.json` 放入公开 Release。发行器只打包白名单；发布前仍需检查 Git 跟踪文件与历史，不把 .gitignore 当作撤回已入库秘密的手段。

## 平台与接入

管理员登录服务器 `/admin/` 查询自己的固定接入凭据，在本机控制台填写服务器 HTTPS 地址及凭据。凭据使用 Windows DPAPI；凭据不进入项目配置文件。重置凭据后所有使用旧凭据的机器都需重新填写。

Windows 构建从官方 CRT 安装目录收集必要 DLL，并检查导入依赖；可用 `--vc-runtime` 指定合法重分发目录。

## 发布操作与接手

1. 在开发根目录先检查工作区，按具体变更运行相关测试。公开发布源使用 `private-workspace/public-source` 独立 checkout；只同步明确审核过的代码和资源，保留该 checkout 自己的 `.gitignore`。不要推送开发根目录历史或整目录复制私有文件。
2. 公开仓库为 `Fuyuky/Ournotes-Assistant`，当前发布分支为 `codex/cloud-refactor`。提交遵循 Angular `type(scope): subject`。先核实远端、分支和待推内容，再从公开 checkout 推送。
3. 固定素材来自 `assets/runtime-catalog`。`.gitattributes` 将其标为 binary，是为了保持摘要对应的精确字节；不要单独规范化 JSON 换行。更换素材时须同步验证快照摘要及指针。
4. 更新 `deploy/client/RELEASE_NOTES.md`，在 GitHub Actions 的 **Portable release** 手动选择已推送分支、三段版本号和 `publish`。`publish=false` 只构建验收；`true` 在 Windows 验证通过后发布。工作流为 `.github/workflows/release.yml`。
5. CI 固定 Python 3.12.10、uv 0.9.9，按锁文件安装依赖，运行构建/更新测试，再在 Windows x64 runner 上构建。`scripts/verify_release.py` 验证包签名、依赖导入、离线 OCR 初始化及隔离目录下 WebUI 启动；不执行游戏，也不证明 MuMu 实机兼容。
6. 发布后核实 Release 标签对应提交、Windows ZIP 的名称和平台、匿名直接下载，以及内置签名校验。公开客户端不携带维护者 token。匿名版本查询 API 与附件直接下载是不同链路，应分别验证；前者可能受 GitHub 配额限制。

当前工作流调用 `gh release create`，只支持创建尚不存在的 Release；重跑同版本不能当作替换流程。若明确获准替换既有版本，先完成新包验证，再单独处理附件及说明，核对标签和源码对应关系。更新器要求版本递增，替换同版本 ZIP 不会让已安装的同版本自动获得升级。

### 凭据与签名

- Actions 的 `RELEASE_SIGNING_KEY` 是项目更新签名私钥，CI 临时写入后删除。正式版本继续复用，不能随意生成新密钥导致旧客户端失去信任。
- 维护 GitHub 授权仅在进程内使用，不得输出或打包。源码 SSH 推送授权与 GitHub API 授权相互独立；CI 发布使用工作流自己的 `github.token`。
- 正式更新签名私钥保存在维护者的项目外私有目录；公开信任锚为 `deploy/client/update-public-key.txt`。

### 已发布基线

上一正式版本为 [v0.1.0](https://github.com/Fuyuky/Ournotes-Assistant/releases/tag/v0.1.0)，对应公开提交 `cae0b84`。v0.1.1 起仅发布 Windows x64；不修改旧版本的历史标签和附件。发布前后须核实远端状态。

## 更新边界

启动只检查版本，不自动下载安装。用户下载时验证签名及哈希；安装须等待控制台与任务退出，并取得客户端、运行、换绑及更新锁。ZIP越界、链接、平台错误和文件哈希异常均拒绝。新版本、启动器和素材验证完成后原子切换 current 指针；发生异常恢复已替换的启动器与素材指针。保留当前及上一版，旧素材不覆盖删除。

升级不会启动游戏、恢复批次、重放邮件或清除未决保护。程序回退不能回退运行数据库和永久编号。下载错误不影响原恢复依据。源代码控制台需退出后重开才能加载 Python 变更。

构建默认清理本次 staging；`--keep-staging` 供排障。验收包大小及测试结论属于任务报告，不能代替真实 GitHub 发行下载、干净 Windows 实机验收。
