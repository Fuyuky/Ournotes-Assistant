# 客户端构建与更新

Windows x64 与 macOS Apple Silicon 使用同一套业务代码，发行包仅按平台区分。没有独立部署版或开发业务版；`devtools` 只放离线诊断工具，不进入发行包。

## 安装布局

```text
客户端目录/
  启动控制台.cmd 或 启动控制台.command
  boot.ps1 或 boot.command
  boot_client.py
  release.json（包内签名清单）
  current.json
  update-public-key.txt
  versions/<版本>/app/
  versions/<版本>/runtime/
  user-data/config/
  user-data/data/catalog/snapshots/
  user-data/state/
  user-data/results/
```

`current.json` 选择程序版本。更新替换程序和启动器、补充固定素材，不能覆盖 user-data 中的配置、数据库和运行记录。成果、账号明细的永久副本只在服务器；本机 results 只用于待确认上传和必要恢复。初装资源只包含当前固定运行素材，不打包整套网站图集或历史快照。

Windows 双击 cmd；Mac 双击 command。运行时随包提供，目标机不用另装 Python。Mac 只支持 arm64 原生运行，不支持 Intel/Rosetta。MuMu 和游戏需要用户自行安装。

启动器通过随包 `boot_client.py` 等待本机接口与首页就绪（最多60秒），再打开浏览器。启动失败保留错误提示；早期启动日志位于 `user-data/state/webui/boot.log`，服务日志位于同目录的 `server.log`。超时不强制结束后台进程。

控制台的 MuMu 卡片可检测安装位置并保存目录至 `user-data/config/mumu.json`；只读扫描常见位置和 Windows 卸载注册表，不运行模拟器。多个候选需手动选择；运行任务期间不能修改。保存后后续操作读取新路径，保留已有 Mac 工具及实例端口配置。显式保存的路径优先于环境变量 `OURNOTES_MUMU_ROOT`，失效时提示重新配置，不静默改用其他安装。

## 构建

正式发布由 `.github/workflows/release.yml` 在 Windows x64、macOS ARM64 runner 分别构建和检查。手动触发可选择仅验证或发布，两个平台均通过后才上传两个 ZIP。`RELEASE_SIGNING_KEY` 放在仓库 Actions Secrets，私钥不进入源码、日志或产物。构建使用仓库内 `assets/runtime-catalog` 的固定素材，不依赖开发机的数据目录。

本机构建使用项目 `.venv` 的 Python。构建器按 `uv.lock` 导出 client 组，下载或接收平台对应 Python 运行时，安装平台依赖，不复制开发虚拟环境。Mac 包可交叉组装，但实际启动、钥匙串、MuMu/ADB、更新器必须在真实 Apple Silicon 验收。

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build_release.py `
  --version 0.2.0 --platform windows-x64 `
  --output results/build-release/正式构建 `
  --signing-key C:\私有发布目录\release-key.pem --download-runtime
```

首次生产密钥明确加 `--generate-signing-key`，以后复用同一私钥。私钥在项目外保存，初装只带公钥；临时验收密钥及用它生成的包不能冒充正式发行。Mac 改 `--platform macos-arm64`。已有运行时用 `--runtime` 和相应摘要；完整参数见 `--help`。统一免安装包必须包含运行素材。

每个平台只生成一个 `ournotes-<版本>-<平台>.zip`，初装和控制台更新共用。Release 只上传 Windows、Mac 两个 ZIP，不另发更新包、签名、公钥或校验码附件；GitHub 自动生成的 Source code 链接不是客户端发行包。

ZIP 内含 `release.json` 的 Ed25519 签名与全部文件摘要，客户端使用已保存公钥验证。清单不对包含它自身的 ZIP 计算自引用摘要，而是验证精确文件集合、每个文件内容、平台、版本和素材指针。下载从公开 Release 获取，无需用户配置 GitHub token。

包中排除账号、数据库、邮箱和接入凭据、Google授权工具、SSH配置、日志、结果、开发工具、测试、Git、缓存、旧版本、服务器后台源码。不能把已配置本机的 user-data 或 `client-connection.json` 放入公开 Release。发行器只打包白名单；发布前仍需检查 Git 跟踪文件与历史，不把 .gitignore 当作撤回已入库秘密的手段。

## 平台与接入

管理员登录服务器 `/admin/` 查询自己的固定接入凭据，在本机控制台填写服务器 HTTPS 地址及凭据。Windows 用 DPAPI，Mac 用系统钥匙串；凭据不进入项目配置文件。重置凭据后所有使用旧凭据的机器都需重新填写。

Mac 使用 `config/mumu.json` 明确配置 MuMu 的 mumutool、adb 绝对路径及实例对应的 `adb_port`。未知实例或未识别的状态字段拒绝操作，不猜测端口。设备图像和点击走平台适配；业务状态机、收码、预设、上传与 Windows 一致。

Windows 构建从官方 CRT 安装目录收集必要 DLL，并检查导入依赖；可用 `--vc-runtime` 指定合法重分发目录。Mac 启动器、执行权限和运行库布局有独立构建校验。实机签名、公证和系统提示仍须在正式发行前验证。

## 更新边界

启动只检查版本，不自动下载安装。用户下载时验证签名及哈希；安装须等待控制台与任务退出，并取得客户端、运行、换绑及更新锁。ZIP越界、链接、平台错误和文件哈希异常均拒绝。新版本、启动器和素材验证完成后原子切换 current 指针；发生异常恢复已替换的启动器与素材指针。保留当前及上一版，旧素材不覆盖删除。

升级不会启动游戏、恢复批次、重放邮件或清除未决保护。程序回退不能回退运行数据库和永久编号。下载错误不影响原恢复依据。源代码控制台需退出后重开才能加载 Python 变更。

构建默认清理本次 staging；`--keep-staging` 供排障。验收包大小及测试结论属于任务报告，不能代替真实 GitHub 发行下载、干净 Windows 或 Mac 实机验收。
