# 测试报告与巡检规范

本文规定统计口径，不记录当前批次或临时授权，不授权启动、恢复、监控或发布。

## 统计范围

- 每次读取当前批次的最新持久化数据，核对 batch_id、读取时间与运行状态，不混入历史批次，不把旧快照或预计结果当作当前数据。
- 仅将当前批次已完整完成、识别无未知项的账号纳入完成样本。
- 未完成账号的已有结果单独列出，不计入完成样本、排行榜、分布或样本频次。
- 报告同时列出原定目标和实际完成数。提前停止不等于原定目标全部通过；没有完整可统计账号时如实说明。

## 五项核心指标

以下指标均以单账号为单位，每项列出最高值和达到最高值的全部并列账号 index：

1. SSR 总张数（角色卡＋支援卡）。
2. 不同 MyGO SSR 角色数。
3. 不同 Mujica SSR 角色数。
4. 不同 SSR 角色数。
5. 当期 up 种数：按账号持久保存的抽卡计划确定对应池；计划精简后从已完成交易的稳定池身份恢复；目前仅 #10、#12，各4种 UP。角色卡与支援卡按 `kind:id` 去重，重复张数不增加种数；同一计划涉及多个已审核池时取 UP 身份并集。无对应池或缺失历史计划标为不适用，不当作0，不纳入本项均值、最高值及分布；列出本项独立样本量。

角色数按角色 ID 去重，同一角色不同卡面只算一个角色；支援卡不计入角色数。不同卡面数另作补充指标。禁止把所有账号的 SSR 张数相加作为账号质量指标。并列 index 必须完整列出，不截断为前几名。

## 最终测试报告

- 列出批次 ID、原定目标、实际完成数、各实例进度、预设及各预设样本量、用时、五项最高记录。
- 提供单账号 SSR 总张数的统计分析和直方图。
- 提供不同 MyGO、Mujica、全部 SSR 角色数的统计分析和直方图。
- 列出本样本最常见和最少见的已出现 SSR；未出现 SSR 另列，说明所用卡牌目录范围。频次口径必须明确。
- 补充按预设比较、重复 SSR、不同卡面等分析。不同样本量用组内比例比较，注明各组 n。
- 样本出现频次不等于真实抽取概率，不据此声称真实概率。
- 未完成账号的已有结果、未知项、中断、人工干预及验证限制单独说明。

## 性能报告

普通运行仅长期保存阶段耗时汇总，不记录逐步骤明细。需要以下完整性能报告时，须在新批次开始前开启调试模式；恢复沿用原设置。详细数据只保留最近一次调试批次，下一次调试批次替换；普通批次不替换。永久保留的是结论摘要与经核实的回归素材，不是每次执行的完整步骤日志。

- 记录各步骤具体耗时，至少提供一个实例的完整分步骤台账，不只提供平均值；步骤文件可附 CSV 或 JSON 供核查。
- 分析截图、UI 判断、字段 OCR、后台卡牌识别、结算页停留、输入及等待成本。
- 区分实际活动时间、日历跨度和暂停时间，注明起止时间及计时边界。
- 并发任务与嵌套计时不得直接相加；单实例步骤台账应有清楚的、不重叠的墙钟时间口径。
- 如实记录异常、中断、人工干预、恢复、离线复核和验证限制，不把有干预的运行表述为全程无人干预通过。

## 聊天中的最终测试汇报

- 给出完成情况、用时、五项最高值和全部并列 index。
- 链接完整测试报告、统计图表及完整步骤记录。
- 使用“角色卡”和“支援卡”，不使用“志愿卡”；聊天不汇报 SR。
- 需要列具体卡牌时，角色卡与支援卡分开，逐条使用格式：`SSR 【卡牌标题】角色名 x1`。

## 授权、巡检与定时汇报

- 仅按用户对本次任务的明确授权创建或启用监控；记录指定批次、频率、通知条件及结束条件。不继承历史批次的授权。
- 定时任务只读核验并汇报，可更新自己的读取时间、快照与汇报时间戳；不得控制模拟器、恢复或作废账号、修改数据库/控制文件/生产代码或替主助手处理异常。
- 半小时汇报时重新读取最新数据，报告北京时间（Asia/Shanghai）、完整有效数/目标、各实例预设和进度、运行/暂停状态、五项最高值及全部并列 index。即使没变化，也按该次授权要求如实汇报。
- 每分钟巡检不是默认任务，只有明确要求时才启用；正常且未到汇报时间保持安静。新异常、介入或完成按授权即时说明，同一异常不刷屏。
- 普通异常暂停是否继续汇报以本次授权为准。用户停止/取消、指定批次已结束或已换批时按任务约定收尾，不擅自跟随下一批。
- “今日邮箱发送次数已达上限”直接停止提示所在客户端及对应监控，不重试、不自行恢复，不能据此停止其他客户端。
- `complete` 状态或进程退出不等于目标样本全部完成；独立核验实际完成数、未知项、未完成账号和原目标。

## 调试与截图

- 聊天优先给结论和少量必要日志，大量细节保存到文件并提供链接。
- 输出按用途归档：批次报告放 `results/batches/<batch_id>/`，专题分析放 `results/analysis/<专题>/`；排障、研究、验收记录分别放 `results/maintenance/diagnostics/`、`research/`、`validation/` 的任务子目录，不在 `results/` 顶层新增临时目录。
- 不回读旧会话，不批量加载历史日志或截图；按批次、实例、账号、事件及时间范围定向读取。
- 普通过程截图仅保留在内存缓存；异常现场按既有规则保留。
- 成功账号归档后不保留原图；报告不要求补留成功截图，不为报告重做抽卡或重新采集成功账号画面。

## 新卡池的统计分类审核

新增卡池时必须判断是否属于“当期 UP 收集”类：核实 hk-tw-mo 主数据的明确 UP 清单、活动期与卡池用途；不能仅因有 UP 或卡池编号较新就自动纳入。常驻、必得、生日及复刻池须单独判断，不默认归类。当前白名单仅 #10（member:61、member:62、support:62、support:63）和 #12（member:65、member:66、support:65、support:66），来源为已核验运行素材的 pickup_card_keys。确认适用后更新 `ournotes/reports/pickups.py`、相应去重/池隔离回归及本文；未确认则保持排除。历史统计按保存计划与稳定池身份计算，不随当前预设名称或活动时间变化。
