# 开发版邮箱换绑

## 使用

源码控制台或 development 构建的“账号与结果 → 账号管理”提供“邮箱换绑”。deployment 构建不含界面、执行器和本机换绑 API。

1. 输入 index，点击“账号换绑”展开面板，在线检查该账号为未使用或已拍下；永久已使用不能换绑。
2. 填写目标邮箱，指定批次之外的空闲 MuMu 实例编号，点击“开始换绑”。例如批次使用 1–4，换绑使用 0，可同时执行；暂停批次中的实例仍不能借用。游戏当前支持 Gmail、Hotmail、MSN、Outlook、Yahoo、iCloud、QQ、163、126；其他域名在启动前拒绝。实例需安装游戏并使用 1600×900。
3. 脚本切换到原邮箱登录，进入用户中心、绑定信息和更换绑定。原邮箱认证链接由服务器处理；新邮箱邮件不由服务器读取。
4. 显示“等待邮件确认”后，打开目标邮箱邮件中的认证链接，再点击“邮件已确认”。游戏提示“邮箱链接尚未确认”时仍停在等待状态，可确认链接后再点击。
5. 成功返回绑定信息并核对 UID 后，自动通过协议 2 的云端状态 CAS 标记账号永久已使用，沿用账号使用状态同步和上架模块通知。已使用账号不能再次换绑。

目标邮箱提交后，局部 OCR 识别到游戏的“邮箱已被注册”提示时，控制台显示“邮箱已注册，请更换邮箱”。判断只使用提示文字，括号中的动态错误码不参与判断。此时目标邮箱输入框恢复可编辑，填写另一个邮箱并点击“更换邮箱并继续”，沿用当前任务、原邮箱认证和密码，不重复登录或原邮箱发信。轮询不会覆盖正在编辑的邮箱；旧页面或重复请求不能再次发信。新目标再次被明确拒绝时可继续更换；未知结果、网络错误和单纯停留在绑定表单仍按原流程停止核查，不开放重发。

原生提示截图保存在当前任务的诊断目录。每次经人工更换目标的提交都建立独立发信记录，并先检查和预留一次追加额度；不清除旧发送记录、不返还已占用额度，不在其他任务运行中自动切换节点。更换邮箱本身不改变账号使用状态，仍须完成最终换绑及 UID 核验才标记已使用。服务重启仍停止并保留中断状态，不恢复已发送的请求。

任务开始时生成 16 位随机密码，任务期间自动显示密码文案。发信提示、密码文案与收货提示直接展示，每条旁边提供复制按钮；不使用文本框或显示/隐藏切换。常规状态接口、磁盘检查点和日志不保存密码。清除任务后不保留。账号档案保留原始来源邮箱；目标邮箱和密码应由使用者自行保存，不进入公共导出。

## 停止及失败处理

成功换绑后，普通样式的“结束换绑”按钮用于收尾并清除当前任务；点击前先复制密码。若后台仍在关闭实例等收尾步骤，会显示“结束中…”，等待清理完成。进行中的任务仍提供红色“停止换绑”，用于中止操作；启动前被拦截且线程已退出时显示普通样式的“清除任务”。结束任务不会撤销已确认的换绑或已使用状态。

“停止换绑”取消后续操作，当前有界请求退出后清除任务输入、密码、短期检查点，撤销云端短期票据并释放实例控制。已经发送的邮件或已经生效的换绑不会被撤销。

对最后一次“下一步”的结果不确定，以及已成功换绑但 used 同步失败，会保留最小账号业务核查记录（index、account_id、状态，无目标邮箱/密码）。这是账号结果保护，不属于可清空的表单任务；停止不会清除它或既有 used_pending。该账号禁止重复换绑，需核查游戏与云端使用状态。云端确认真实 usage_status=used 后，后续检查会移除对应保护记录。换绑中可以撤销已拍下，但不得清除该保护；确认游戏成功后的 CAS 冲突只重新读取并提交状态，后台连通后继续核对和推进终态，不重复游戏换绑。

启动前被拦截时，按钮显示“未启动换绑”，页面分别解释数据库占用、表或字段缺失、状态文件读取失败、批次正在收尾、实例保留、账号未完成或控制者协议不兼容，并给出处理建议。展开“诊断信息”可查看错误编号、来源、异常类型、系统/SQLite错误码及发生时间；不会显示原始异常、邮箱、密码或认证信息。等执行线程释放锁后可点击“清除任务”，不会自动重试。

启动校验失败的安全诊断同时保存到短期检查点和 `results/maintenance/diagnostics/email-rebind/<task_id>/failure.json`；清除任务仍保留诊断文件及账号业务核查记录。意外重启时，已确认启动前被拦截的任务保留原因和建议，不重放操作。未确认阶段或已经进入游戏流程的任务仍显示“服务曾中断”，密码已丢失，核查后停止清除。原始编号、账号档案、抽卡交易、批次状态均不变。

游戏已确认换绑成功后，先完成 SDK 断开与票据清理，再关闭该任务使用的单个实例，最后释放实例锁；不关闭其他实例。云端 used 尚待同步时也关闭已成功换绑的实例，并继续保留 used_pending 保护。尚未确认换绑、停止或异常时保留现场，不按成功关闭。关闭结果记录在任务状态中，失败不撤销已确认的换绑或 used 状态。

同一数据根仍只执行一个换绑任务，持有 `email-rebind` 和所选 `device-<instance>` 锁，直至 SDK 断开、云端票据清理请求结束。批次使用独立的 runner 调度锁，并持有其全部实例锁；新批次和恢复在修改业务状态前取得锁，冲突则拒绝。普通批次收尾只关闭本次实际控制过的批次实例，独立换绑不会被批次关机波及。

启动换绑时以 SQLite 只读快照核对批次、run、账号和交易：所选实例不属于任何未结束批次或任务，账号须已完整完成、不是活动账号、没有 submitted/captured/needs_review 交易，本机与云端身份一致。暂停批次即使没有进程也保留全部实例。只在活动调度器的批次和状态匹配且发布 `device_lease_protocol=1` 时允许并行；旧调度器须按授权安全暂停，退出并重开新版控制台，再由用户恢复。刷新浏览器不能重载 Python，升级不自动恢复任务。

发信前记录意图，登录/认证票据独立。准备票据遇到暂时传输失败时，在共90秒预算内最多尝试六次，复用同一请求ID并接受停止，不重新发送游戏邮件；业务冲突、权限错误和授权失效不重试。游戏发信结果不明确不重发。认证 HTTP 请求提交前在云端落下 uncertain 状态，进程崩溃或响应丢失不会重放链接。客户端对收信接口的暂时网络错误只轮询同一票据；遇到服务端 uncertain/review 则停止核查。

Google 刷新返回 invalid_grant 时，服务器以 HTTP 424 和 gmail_authorization_required 明确报告授权失效。页面提示重新完成“接入与检查 → 管理员 Gmail 首次授权与迁移”的浏览器授权及安全迁移；重启控制台或服务器不能代替重新授权。安全诊断记录 HTTP 状态码和受控错误编号，不保存 Google 响应正文、凭据或邮件内容。

SDK 灰色加载框优先于其下方的标题或菜单识别，加载中不输入。打开标题菜单时，若画面仍为可操作标题页，最多尝试三次，按 3 秒、6 秒间隔重采再点击；普通导航上限 30 秒，观察到加载时使用从该次导航开始计算的 120 秒总上限。发码、提交登录和换绑确认不适用该重试。停止后遗留的换绑子页只通过返回按钮退回原邮箱登录，不重放原任务的发信或最终确认。异常保留一张原生截图及不含邮箱/密码的当前步骤信息，位置为 `results/maintenance/diagnostics/email-rebind/<task_id>/`，停止清空表单后仍可用于诊断。

邮箱域名列表按原生边框和局部画面稳定性确认展开，局部 OCR 查找完整、可见的目标域名，滚动到边界后反向查找。无需同时识别两项；提示遮挡、OCR 框抖动或滚动惯性不会直接判定列表无法加载。点击前重新确认前景、域名及位置，列表变化时只重新采样；选择后核对输入框域名。QQ、163 等隐藏项必须滚动后按文字选择，不按列表序号猜测。

## 云端启用

代码提供 `/api/cloud/v1/rebind/capability`、`POST /rebind/tickets` 和 `POST /rebind/tickets/{id}/{arm|poll|cancel}`。默认所有节点禁用。服务器配置新增：

```json
{"rebind_nodes": ["已批准的开发节点ID"]}
```

这是既有云端配置的新增字段，不能用该片段替换完整配置。需要服务器代码更新、原有 Gmail 凭据/代理/验证码规则，以及明确的开发节点授权。客户端先检查协议版本和权限，通过后才连接实例。生产服务器切换与权限启用属于独立部署操作，源码修改不会自动执行。

服务器精确核验收件人、时间窗、消息基线、Google DKIM 结果和唯一候选。原邮箱认证邮件不使用固定发件人白名单，仍要求单一发件地址及 Gmail 确认的 DKIM 签名域与该发件域一致。A 认证仅接受 `game-intl.biligame.net/email_verify/result.html` 中 `mail_change_current_verify` 类型，调用固定官方 `mail.confirm` 接口且禁止重定向；退订及 B 的 `mail_change` 链接不处理。链接参数不返回客户端、不写日志。票据有效期 5 分钟，定期清除短期秘密，消息认领防止重复消费。

原邮箱登录验证码的发件人名单复用服务器 `mail_rule`，与普通登录的收码规则一致；仍要求 Gmail 确认的 DKIM 签名域与发件人域一致，并核验精确点号别名、主题和验证码格式。原邮箱认证链接不按登录发件人名单筛选，由精确收件人、时间窗、DKIM 与固定官方链接规则核验。

## 代码与验证入口

- `ournotes_dev/email_rebind/service.py`：单任务、取消/请求幂等、密码内存、业务核查记录、used 同步与安全诊断持久化；`preflight.py` 以只读快照核对批次/账号并区分启动拦截原因；共用锁在 `ournotes/common/devices.py`。
- `flow.py`、`vision.py`、`assets/`：MuMu SDK 状态驱动执行、原生 ROI 模板、局部 OCR、双向域名列表查找。复用 InputPolicy 的抖动及输入间隔，点击前重采前景。
- `web.py`、`static/`：仅开发版的账号管理交互；受共用本机同源/会话令牌保护。
- `ournotes_dev/extensions.py`：组合上架和换绑扩展，部署客户端不导入。
- `ournotes/cloud/rebind.py`：受限云端票据与原邮箱链接确认。
- `tests/test_email_rebind*.py`：离线票据、权限、未知结果不重放、状态/停止、部署隔离、前景守卫回归。
- `tests/test_device_concurrency.py`、`test_multi_runner.py`：跨进程互斥、双向启动、暂停实例保留、账号保护、清理顺序和关机范围；诊断、迁移及更新也须遵守换绑锁。

测试使用项目 `.venv`。真实流程研究、开发验收记录与一次性样本分别位于 results/maintenance/research 和 validation，不以离线测试代替生产部署或真实换绑验收。

换绑文案提供发信提示、含当前密码的交付文案、收货与改密提醒。任务开始后自动加载密码文案；复制使用已加载的文本，失败则选中文案供Ctrl+C手动复制。密码只在页面内存展示，不写浏览器持久存储，结束或切换任务立即清空；迟到的密码读取响应不能重新显示已结束任务的密码。
